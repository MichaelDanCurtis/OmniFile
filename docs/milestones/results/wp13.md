# WP13: visual views in the portal

The owner asked (2026-11-04) for a more tactile portal that shows "your file is here, your file goes there". WP13 builds three views, in the portal's own tier colours, light and dark.

## What is built

**File journey** (file drawer, files only): `portal/src/features/files/visual/FileJourney.tsx`.
- A track of five stations: Edge cache, Hot, Cool, Cold, Archive. The file's station is highlighted, with a ring that slides when the tier changes. The Edge station shows whether the gateway keeps the whole file or a stub.
- Each station's hint comes from the backend's capabilities (minimum days, whether a read needs a restore). The tooltip names the provider's class: Azure Cool, S3 Standard-IA, "S3 Glacier Flexible Retrieval or S3 Glacier Deep Archive", and so on. Smart lights Hot, Cool and Cold together.
- The next move is one sentence from the scheduler's own fields, for example "Moves to Cold on 21 Nov 2026, Archive on 18 Feb 2027."
- Pins and holds show who set them and until when, as far as the caller's role and read access allow. A keep-online hold shows a band over the track and a meter ("10 of 14 days left").
- An active recall shows as a chip that travels from Archive back to the Edge through the four steps. The step name, the step number and the recall's ETA with its confidence are given as text. Before a recall, the times come from `recall-options`, so no time is ever shown above the no-promise size.

**Share map** (share page, above the settings): `portal/src/features/shares/visual/ShareMap.tsx`.
- Columns: people on site, the gateway (whole files, stubs, arriving, not local), the live account and the archive account (or one account), and the S3 source while a migration runs. Each node gives files, bytes and a bar.
- Recalls in flight move along a lane, by step. Migrations move along their own lane, with counts for an ArchiveAdmin.
- Each node is a button that opens the list of its files (`?node=` in the URL), linked into the file browser.

**Policy timeline** (policy editor, question 2): `portal/src/features/policies/visual/PolicyTimeline.tsx`.
- The schedule as segments with a draggable handle per boundary. The handles edit the same form state as the day inputs, so the live preview, cost and checks follow every move. The inputs stay the typed alternative.
- Each handle is an ARIA slider. Arrows move it a day, Shift+arrows ten days, Page Up and Page Down thirty, Home and End to the ends of its range. A boundary can't pass its neighbours.
- A `minimum_duration` check (and any error on a day field) is drawn on the boundary that causes it: a flag on the handle, the tier hatched, and the message linked to the handle with `aria-describedby`.
- Smart draws one Smart segment and only the archive handle, counted from the write.

**Accessibility.** Reduced motion (`prefers-reduced-motion`) turns off every transition and animation and keeps the same text (tests compare it). Every view has a colour key. The text colours are the tiers' ink shades on their soft shades, and the marks are outlined in the ink shade. The contrast was computed for both themes: text is 5.2:1 or more, and marks are 3:1 or more. The tier amber alone is 2.3:1 on white, so it is never used on its own for a mark. The views reflow at tablet width (820 px screenshots).

## New routes (portal-api.md 5.22; YAML tag `visual`)

All three routes are read-only.
- `GET /v1/files/{file_id}/journey` (read on the file). It returns the backend's ladder from `capabilities_for()`, the account that holds the copy, and the pin and holds. `set_by` and `reason` follow `list_pins` and `list_holds`: the caller needs the role (ArchiveAdmin, DataSteward or the share's Owner) and read on the item the pin or hold is on. `set_by` also goes to whoever set it. Everyone else gets null.
- `GET /v1/shares/{share_id}/map` (anyone who can see the share). It gives edge buckets, stores per backend, account and tier, and recalls by step.
  - ArchiveAdmin and DataSteward get `scope: all`, counts only (the owner's decision, 2026-11-04). The counts come from the worker's hourly count, the `share_map` sweep into `catalog.share_map_count` and `share_map_run` (migration 0036, `usage/share_map.py`), so a page view never walks the catalog. Before the first count the map shows the shape with no totals (`basis: none`).
  - Everyone else gets `scope: readable`, counted live (`basis: live`): files they can read, in folders they can read, reached only through readable folders. The count stops after 3 s (`basis: none`).
  - Recalls are always counted live, from the active-recall index. `migrations` is for ArchiveAdmin only. Both map routes are on the preview rate limit.
- `GET /v1/shares/{share_id}/map/files` lists the files behind one node: only readable files in readable folders, for every role, ArchiveAdmin and DataSteward included.

The routes are in `service/src/omnifile_service/web/routes_visual.py`, registered in `web/app.py` (three lines). The worker job is one more `SweepJob` in `worker/usage_jobs.py`. The mock is `portal/src/mocks/visual.ts`, wired into `handlers.ts` by one spread. `schema.gen.ts` and `examples.gen.ts` were regenerated.

## Review fixes (independent review of #40)

Each fix has a test that fails without it. The service tests include new ACL fixtures (`_acl_world`): a restricted folder holding an open-ACL file, a deny entry, a pin with a reason on the restricted folder, and a nested folder share.
1. Blocking: `map/files` listed files inside folders the caller can't read. The walk now goes only through readable folders, so every listed file's folder is one the caller can open (`test_map_files_never_names_a_file_in_an_unreadable_folder`).
2. The readable map totals had the same gap; they use the same walk (`test_readable_counts_skip_unreadable_folders_and_denied_files`).
3. The journey showed who set a pin or hold, and why, on a folder the caller can't read. It now checks each item as `list_pins` does (`test_journey_hides_who_and_why_on_a_folder_the_caller_cant_read`).
4. The map cost a walk per page view. Admin and steward totals now come from the hourly count; the live readable count is time-limited and on the preview limiter (`test_map_gives_admins_and_stewards_the_workers_whole_share_count`, `test_a_readable_count_that_runs_out_of_time_shows_no_totals`, `test_the_map_routes_are_on_the_preview_limiter`).
5. The journey said "Moves to Archive on …" under an `override_archive` pin. It now says the pin keeps the file out of Archive (journey test "doesn't promise Archive…").
6. The timeline clamped a typed 5000 to 3650 on the first arrow key. A handle now never clamps a value it didn't set (timeline test "never clamps a typed day…").
7. The failed recall chip was 2.2:1 in dark mode; it now uses the accent ink (`contrast.test.ts` reads the tokens and checks both themes).

8. Re-review minors: the hourly count now takes one transaction per share and counts each share's own files only, so nested subtrees are walked once and a failure leaves the other shares current (`test_each_share_counts_its_own_files_in_its_own_transaction`). The live count puts back the `statement_timeout` it found (`test_the_live_count_puts_the_previous_statement_timeout_back`).
