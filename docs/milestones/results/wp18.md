## 1. Activity: live

The page now opens with a live panel above the daily dashboard (`portal/src/features/activity/live/`).

- **Feed.** Uploads, recalls (each state), tier moves, edge heartbeats, migrations and annex events, newest first. New rows rise in and carry a faint highlight for one poll. A polite live region says how many arrived.
- **Counters with sparklines:** uploads per minute (and in 15 minutes), bytes moved in 15 minutes (uploaded plus recalled), recalls in flight, edges online. The first two come from the service's 30-minute per-minute series; the other two from the page's own polls.
- **Edge strip:** each edge's status, uploads and open recalls in 15 minutes, outbox, and when it was heard. A chip filters the feed to that edge.
- **Filters:** kind (toggle pills), edge, share and person. They apply to what has arrived, so they act at once.
- **Pause and resume.** Paused, no request is open and the list holds still. On resume the loop carries on from its cursor, so what happened meanwhile (up to 15 minutes) comes in at once.
- **Reduced motion:** the global rule in `theme/motion.css` stills the row entrance, the live beat and the dot field.
- Activity is now a lazy chunk.

**Service: `GET /v1/activity/live`** (`web/live.py`; portal-api.md 5.13).
- An efficient long-poll, not SSE: one transport through the rate limiter, MSW and jsdom alike. With `since`, `wait` (0 to 25 s) holds the request until something newer exists. It probes every 2 s with one query of six `EXISTS`, each a short index range, and holds no catalog connection between probes. A replica holds at most 32 waiting polls (`live_max_waiting`); past that it answers at once with `capped: true` and `next_poll_s: 10`.
- Every source is read by time through an index. Migration 0043 adds three: `file_version (committed_at)` for edge commits, `recall_state_log (at)`, and `partner_event (created_at)` for migrations. Tier moves come from `audit_log` (`tier.move*`) and annex events from `annex_event`, both by their `(at, …)` keys. Heartbeats come from `catalog.edge`.
- Each source is read from `since` less 30 s, so a transaction that committed late still shows. The page drops ids it has.
- **RBAC:** the gate is `GET /v1/activity`'s (ArchiveAdmin; apps with `Archive.Read`). A file's name, path and id are given only when the caller's AD groups may read it (`access.can_read_sql`, decision 28). Otherwise `hidden: true`, and the page says "a file you can't read". An ArchiveAdmin who isn't in a folder's ACL sees no names in it; an app sees none. A migration's prefix is never sent. Unreadable folders above a readable file show as `…`.

## 2. Edges: the Add edge wizard

`/edges/new` (`features/edges/AddEdgeWizard.tsx`); Add edge on the Edges page links to it. The old dialog is gone; New code on a pending edge is unchanged.

1. **Platform:** Hyper-V (VHDX), VMware vSphere (OVA), KVM or Proxmox (qcow2), Azure VM (VHD). AWS EC2 is shown locked: no EC2 image is built.
2. **Image:** the file name `appliance/convert.sh` writes, `omnifile-edge_<release>.<ext>`, for this service's release. A release publishes only the update feed online today, so there is no download URL. The step says the images are in the release folder's `appliance-files/` with `SHA256SUMS` (customer guide 1.7), and that a link appears once the operator sets `OMNIFILE_APPLIANCE_IMAGES_URL`. Then the import commands, from the customer guide 11.1 to 11.3. The Azure VM path is marked as not yet tried on a subscription.
3. **Requirements:** the VM's size (guide 1.6), and the network (guide 1.2 and the appliance's `firewall.nft`): ExpressRoute or VPN, outbound to the DCs, time and the service on 443 and 8443, the inbound ports, and the AD needs (join account, admin group with `gidNumber`, admins with `loginShell`).
4. **Enrol:** the name, then the code from `POST /v1/edges`, with Copy, its expiry and the time left. Then the console steps as `omnifile-setup` asks them, and `sudo omnifile-setup enrol` for a filer already set up. For KVM, the unattended form: the `omnifile.setup` and `omnifile.enrol-bundle` credentials through SMBIOS type 11, as `appliance/tests/vm.sh` passes them.
5. **Online:** polls `GET /v1/edges` every 3 s. Code created, then Enrolled (state `active`), then First heartbeat, each turning green.

**Service: `GET /v1/edges/appliance`** (ArchiveAdmin, session only): the release (the service's PEP 440 version written back as the release's `VERSION`), each platform's file, `url` only from `OMNIFILE_APPLIANCE_IMAGES_URL`, `enrolment_configured` and `code_ttl_s`.

## 3. Prices: who sees them, and the rates

Settings, Prices and alerts (`features/settings/Prices.tsx`).
- **Who sees prices:** presets (Everyone, Admins only, ArchiveAdmins only, Nobody), and each role one click down (ArchiveAdmins, DataStewards, Everyone else). Saved with `If-Match`; the page shows who changed it last.
- **The rates:** per class, per GB-month, writes and reads per 10,000, retrieval per GB, editable. A rate that differs from the list price shows the list price under it. Reset puts one class back; Reset all to list price deletes the override. S3, which has no built-in table, lists its classes empty to fill in.

**Service** (`web/prices.py`, `routes_admin.py`; portal-api.md 5.24):
- `GET` and `PUT /v1/settings/prices {show_to}`: ArchiveAdmin, signed in, with an AD identity. Stored in `catalog.price_display` (migration 0043) and audited as `settings.prices.visibility` with `from` and `to`.
- A user sees prices when any of their roles is listed; `GET /v1/me` says so in `prices_visible`.
- For a user who doesn't, the endpoint wrapper removes every amount from every answer: each `Money` object becomes null, and lists of them lose their entries. That covers every route that prices something, including idempotent replays. `GET /v1/price-tables/{kind}` is `403 forbidden` for a hidden DataSteward, while ArchiveAdmins' editor still reads the rates. Partner applications keep their amounts.
- The setting is cached 10 s per replica; the replica that changes it forgets its copy at once.
- `GET /v1/price-tables/{kind}` adds `list`, the built-in table. A `PUT` ignores it.
- The YAML's five non-null money fields (policy preview costs, cost items, recall costs) are now nullable.

**Every place that shows a cost respects it:** the policy preview's cost card and the editor's summary line, the pin dialog's fees, check fees and recall fees (null, so not shown). The service sends no amounts anyway.

## The review of #63

Each fix has a test that fails without it.

1. **Blocking: apps skipped the API-client owner rule.** An app now sees only the datasets its client's owner may see (`apiclients.access.datasets_owner_can_see`, the same rule as `owner_can_see_dataset`), in its events, series and the edge strip's counts. An app is never given `person`. Test: `test_an_app_sees_only_its_client_owners_datasets_and_no_people`.
2. **A row dated ahead made every page busy-loop.** The probe now stops at now, as the answer does, and `next_poll_s` is never under 2 s. Test: `test_a_row_dated_ahead_does_not_end_every_wait`.
3. **The share filter ran after the limit.** Every filter (share, edge, person, an app's datasets) now applies inside each source, before its limit. A share is resolved in SQL: its dataset, under its root, and not under a share nested in it. An unknown share is `404`. Test: `test_the_share_filter_applies_before_the_limit_and_skips_nested_shares`.
4. **0043's indexes blocked edge commits.** `catalog/migrate.py` has a `-- migrate: no-transaction` mode, and 0043 uses it:
   - each statement runs on its own and may run again;
   - the migration is recorded only when all have run;
   - the indexes are built `CONCURRENTLY IF NOT EXISTS`;
   - an invalid index left by a failed concurrent build is dropped before the build runs again, and every index must be valid afterwards.

   The runner now polls for its advisory lock (`pg_try_advisory_lock`) instead of waiting on it. A runner blocked inside `pg_advisory_lock` holds a transaction that another runner's concurrent build waits for, which is a deadlock; the existing concurrent-runners test hit it. That test now fails on any runner that dies. Tests: `test_a_no_transaction_migration_builds_concurrently_and_recovers_a_failed_build`, `test_0043_runs_outside_a_transaction`, `test_concurrent_runners_apply_each_migration_once`.
5. **Minors:**
   - a refusal's amounts (policy_invalid's `checks[].fee`) are removed for a hidden role too (`test_a_refusal_carries_no_amount_for_a_hidden_role`);
   - the long-poll cap is at most twice the catalog pool, so 8 on the small profile (`test_the_cap_follows_the_catalog_pool`);
   - a rate above 10,000, or longer than 24 characters, is `400 invalid_request`, not 500 (`policy/cost.py`, `test_a_huge_rate_is_refused_not_a_500`).
6. **From the re-review:**
   - an app may not filter by `identity_id` (`400`): with `person` null, the filter would still say whose events they are;
   - the runner's wait for its advisory lock has a deadline (`lock_wait_s`, 10 minutes), and says another runner holds it;
   - no-transaction statements run under `lock_timeout` (`build_lock_timeout_s`, 5 minutes). A concurrent build held by an open transaction on its table fails with the statement and a pointer to `pg_stat_activity`;
   - any `CONCURRENTLY` other than `CREATE [UNIQUE] INDEX CONCURRENTLY IF NOT EXISTS <name> ON <schema>.<table>` is refused before anything runs. The post-build validity check has its own test.
7. **Customer guide, step 53:** the wizard's first step has **Skip to the code**, for a VM that sections 11 and 12 already made. Step 53 clicks it before it fills Name, and the text says what the wizard is. A vitest replays the step as written.
