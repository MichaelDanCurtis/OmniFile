# WP14: Annex phase A1 (Copy mode)

Branch `claude/annex-a1`. The design is `docs/design/annex.md` (decision 51); this builds its A1 section: a Copy annex on any NFS or SMB server, ONTAP and PowerScale included as generic servers. Nothing is ever written to the NAS.

## What is built

**Catalog** (migration `0038_annex.sql`, after #45's 0037, now on main):
- `catalog.filer`, backend kind `nas` (one row per filer, added through the owner-run `catalog.nas_backend_add`, because `web` has no INSERT on `catalog.backend` since #43), and source kind `annex`.
- `catalog.annex` (mode `copy` only), `catalog.annex_ruleset` (the fixed Copy template, approved at creation by the person creating it, or `proposed` when an app creates it, until a person approves it), `catalog.annex_file`, and `catalog.annex_event`, partitioned by day. The worker's partition upkeep keeps 14 days ahead, and `default_partition_rows` covers it.
- `catalog.annex_defaults`, the Settings defaults.
- ACLs captured from a NAS keep their raw descriptor (`acl.raw_kind`, `acl.raw`). NT and NFSv4 ACLs are evaluated deny-first (`acl.deny_first`, and a 5-argument `catalog.acl_can_read`), so a group deny is never outvoted by a group allow. `web/access.py` and `notify/facts.py` pass it.
- A trigger records each copy's verification on the annex file, with a `verified` event. On Azure most copies are verified at commit (`upload_block_crc`: Azure checked every block's CRC as it stored it); a copy without per-block CRCs, and every copy on the simulated backend the exit test runs on, is read back in Azure by the `verify` queue (`azure_read_crc`, decision 24). A2's removal gate needs the in-Azure read (design §3.3).
- Drift from reconciliation goes to `catalog.reconcile_drift`, source `annex`, with four new kinds.
- Per-app privileges for all of these.

**Service:**
- Control API §4.8: `GET annexes`, `POST annex-events` (batches of up to 1,000, a savepoint per event, idempotent by batch), `GET annexes/{id}/records` (for reconciliation). Events: mount, scan, baseline, arrived, changed, copied, left, renamed, drift, skipped, copy_failed. The service parses NT security descriptors itself.
- Annexed files are `remote` with nothing resident (`api/data.py`), so nothing stubs or fills them, and annex datasets are left out of the edge's feed. A share on an annexed dataset is refused (`409 dataset_annexed`).
- NAS deletes are tombstones; the copy, and every older version of a changed file, is kept until an ArchiveAdmin purges it (decision 51): depth pruning (`retention/depth.py`) skips annex datasets. The worker purges (`annex/purge.py`): it prunes the versions and deletes their blobs, and WORM or a legal hold refuses it, recorded. The optional per-annex deleted-file retention is a daily sweep, off by default.
- Portal and partner API §5.23: `/v1/filers`, `/v1/filers/{id}`, `…/health`, `/v1/annexes` (Copy only, `422 mode_not_available` for the rest; an app must name an owner in the Owners group: `422 owner_required`, `403 owner_lacks_access`), `GET/PATCH /v1/annexes/{id}`, `…/events`, `…/files`, `…/timeline`, `…/problems`, `…/files/{id}/purge`, and `GET/PUT /v1/settings/annex-defaults`. Files and their events are filtered by each file's captured NAS ACL (decision 28). All enums are open. YAML, contract docs and the generated client are updated.

**Edge** (`edge/crates/omnifile-edge/src/annex/`, binary `omnifile-annex`):
- `omnifile-annex@<id>.service` runs one annex in its own mount namespace; `omnifile-annex.service` starts and stops those units from `GET annexes`. Both are in the appliance image (with `cifs-utils` and `nfs-common`); the image itself was not rebuilt.
- The mount is read-only, `nosuid,nodev,noexec`, and `nosymfollow` (set again by a bind remount, which the helpers need), and checked (statvfs flags, readable) before anything is read. Every read of the NAS goes through `nasfs.rs`: the annex root (its `path` checked plain and relative) is held as a directory fd, and every open and stat is `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS | RESOLVE_NO_XDEV)` or a single-component `statx` with `AT_SYMLINK_NOFOLLOW`, so no symlink or mount below takes a read outside the annex. SMB uses Kerberos with the edge's AD computer account from the host keytab, or a service account's keytab; NFS uses `sec=krb5`, or `sec=sys`, which the portal labels host-trusted.
- `annex.db` (SQLite): the listing, the outbox, the copy journal. The baseline scan, quick scans (directories whose mtime changed; a directory changed in the last 10 s is read again until it settles, because NFS and SMB clients cache listings), full scans, renames told from deletes by file id, and SMB change notify as a hint only.
- The quiet period (two looks Q minutes apart) and the SEG-Y structure check (whole traces; an incomplete file is copied after 24 hours with a problem recorded).
- Copies through the existing uploader: a hash pass bracketed by `statx(AT_STATX_FORCE_SYNC)`, the file's cached pages dropped (`POSIX_FADV_DONTNEED`), an upload pass of the file opened beneath the root and checked block by block against the hash pass, then a forced re-stat before the upload is completed: a change discards the pending version and sends no `copied` (design §2.2). A read error that isn't a change is tried three times, then `copy_failed`. Plain blobs with `file_owner`/`file_group`/`file_permissions`, per-block CRC64, no tier. The op id is the file and its NAS attributes, so a restarted unit gets the same upload, or `dedupe` once committed: never two commits.
- ACL capture: `system.cifs_ntsd` (the raw NT descriptor) over SMB, `system.nfs4_acl` (raw, with SIDs mapped through winbind) over NFSv4, POSIX mode and ACL over NFSv3. It fails closed: over SMB or NFSv4 without a readable ACL the file is skipped (`acl_unreadable`), never described by the mount's uid, gid and mode, and the service accepts only the kind each protocol sends.
- Weekly reconciliation: a fresh walk against the catalog's record (an unreadable root aborts it; records under an unreadable folder are not judged, and the folder is reported `skipped`), drift rows, then the fix (missed arrival or change copied, missed delete reported, a copy that no longer matches copied again under a new op id).

**Portal** (`portal/src/features/annex/`): Annexes list; Create an Annex (steps 1, 2 with Copy only, 4, 5 and 7, with an inline Add a filer and More settings); the Annex page (header with mount health, timeline of arrivals and departures with copies, files with the NAS stop on the tier track, problems, pause, and purge after a confirmation; an app-proposed annex waits for an Owner's or ArchiveAdmin's approval there). The New migration wizard's Annex kind now hands over to Create an Annex with the filer and folder. Settings has Filers and Annex defaults.

## Review fixes (#51)

Independent reviews of the edge and the service found 4 blocking, 4 should-fix and 8 minor issues. All are fixed, each with a test that fails without its fix (the service's checked by removing each fix again; the edge's test behaviour the old code got wrong, through the new interfaces, so they don't build against it):

- **Edge, blocking:** an unreadable folder counted as deleted in reconciliation (and in a quick scan whose stat failed): now kept, reported `skipped`, never `left` (`an_unreadable_folder_is_never_a_delete`, `reconciliation_with_an_unreadable_root_judges_nothing`). ACL capture fell back to the mount's synthetic owner and mode: now fails closed (`no_readable_acl_fails_closed_never_the_mounts_mode`).
- **Edge:** path confinement (`nasfs.rs`; `a_symlink_in_any_component_is_never_followed`, `a_folder_swapped_for_a_symlink_is_never_followed`, `symlinks_on_the_nas_are_never_followed_or_copied`, `a_mount_without_its_vfs_flags_is_refused`); a change after the upload pass was recorded as copied (`a_change_after_the_upload_pass_discards_the_version`); EIO looped forever (`a_persistent_read_error_fails_the_copy_after_bounded_tries`); NFSv4 ACE order and denies (`nfs4_aces_keep_their_order_and_their_denies`).
- **Service, blocking:** the worker would have pruned annex copies a day after a NAS delete or change (rewind depth 0 on a shareless dataset): annex datasets are never depth-pruned (`test_an_annexes_copies_are_never_pruned_by_depth`).
- **Service:** a changed file whose new ACL can't be read kept the old one (now none: `test_a_change_whose_acl_cant_be_read_drops_the_old_acl`); `posix` accepted from any filer (now one kind per protocol: `test_a_filers_protocol_decides_the_acl_kind_it_may_send`, `test_a_posix_acl_from_an_smb_annex_leaves_the_file_unreadable`); callback allow ACEs counted as allows (`test_callback_allows_grant_nothing_and_callback_denies_still_deny`); the owner rule for apps (both the named owner and the client's owner must see the dataset, the Owners group is never the owner alone, an app's rule set stays `proposed` and the edge doesn't start it until a person approves it with the new `POST /v1/annexes/{id}/ruleset/approve`, app PATCH scoped the same way: `test_an_app_names_a_person_who_owns_the_annex`, `test_the_edge_never_starts_an_annex_waiting_for_approval`); NAS paths of path-only events and drift shown only to ArchiveAdmins and apps, counts and reasons to others; re-auth for a purge and a deleted-file retention, and a confirmation in the portal (`test_the_annex_page_shows_what_the_nas_lets_you_read`, portal `annex.test.tsx`); `purge_due` filters due rows in its SELECT (`test_a_retention_purges_the_due_files_whatever_waits_before_them`); narrower grants (`test_the_apps_write_only_the_annex_columns_they_need`); the verification docs.
- **Re-review (round 2):** an app-proposed annex can't be approved by the owner the app named or by anyone answering for its API client (`registry.answerable` and `check_approvable`, `403 self_approval`; the rule set now records the client and key), and the client and its owner are checked again at approval (`test_an_app_names_a_person_who_owns_the_annex`); an app's reads of events, files and problems need its client owner's access (same test); the `purge_due` test is rebuilt with two annexes so it fails on the old query (`test_a_retention_purges_the_due_files_whatever_waits_before_them`); and the last forced stat now runs after every block is staged and before Put Block List (`BlobClient::upload_file_gated`), so a last-moment change commits nothing in Azure: no orphaned, billed, possibly WORM-locked blob (`a_change_after_the_upload_pass_discards_the_version` with a Fake that counts commits, aborts and orphans; `a_closed_gate_commits_nothing` against the blob sim). Each was checked to fail with its fix removed.
- **Exit test:** the exports are now `strictatime`. The test reads with `O_NOATIME`, the "nothing written" digest leaves atimes out (mtimes, ctimes, modes, owners and bytes stay in), and a new check shows the annex's reads moving atime: a read, not a write, but an `accessed_age` rule on the NAS sees it (documented in the test). A new check compares each SMB file's read set with what its server-side mode grants.

## What the exit test found and fixed

- Quick scans missed changes made moments after a scan: the clients' cached listings gave a fresh mtime with a stale listing. Directories changed in the last 10 s are now read again until they settle (`scan.rs`, test `a_directory_changed_moments_ago_is_read_again_until_it_settles`).
- Over SMB, a NAS delete was missed by quick scans for over a minute: the client held a directory lease (kernel 7.0 caches leased directory handles even with `nohandlecache`), its cached attributes kept the folder's old mtime, and the test's Samba 4.23 never broke that lease for the delete (`smbstatus` showed the annex's RH lease on the folder; `/proc/fs/cifs/open_dirs` its stale entry). The SMB mount now adds `nolease`, so no directory is cached (`mount.rs`, asserted in `every_mount_is_read_only_with_the_machine_account_by_default`).
- The test itself first wrote behind the servers' backs, where their caches hid the change from every client; it now writes as users do, over SMB (another AD user, Kerberos) and NFS.

## Environment notes

- The test Samba server is a separate computer account, `A1NAS`, joined to the dev AD (its state is in `/mnt/ext/wp14/smb-state`). Its first `net ads join` overwrote `omnifile-acl`'s `/etc/krb5.keytab` for about two minutes; ACL1's keytab was restored from its own secrets (`net ads keytab create -P`), WP9 was told, and the test now guards the system keytab around a join.
- A Samba server with `idmap_ad` can't map a computer account without a uidNumber, so the edge's machine account gets its ticket but `A1NAS` refuses it. The SMB annex in the test uses `service_keytab` (an AD user's keytab). Real NAS servers map computer accounts; confirming that on ONTAP is a site check.
- NFS `sec=krb5` needs an `nfs/` SPN on the test server, a change to the shared DC, so the NFS annex in the test is `sec=sys`.
