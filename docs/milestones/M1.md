# M1: vertical slice, work breakdown

`docs/BUILD-PLAN.md` M1 says *what*. This file says *who builds which part and against which contract*. M1 is committed on branch `claude/m1-slice`, stacked on M0 (`claude/m0-foundations`).

**Exit (from the build plan):** a file copied to the NFS share appears in Blob with a matching CRC64, becomes a stub, and reads back byte-identical on NFSv3, 4.1 and 4.2 under `wait` and `failfast`. The ported B1–B5 and fail-closed tests pass.

In M1, "Blob" means the **sim Azure Blob HTTP facade** (`service/src/omnifile_service/backends/sim_http`). The same edge code is run against a real Azure account later (test strategy, layer 3).

## Contracts every track builds against

These are authoritative. If code needs them to change, change the doc in the same change and tell the other tracks.

- `docs/contracts/fsal-socket.md`: FSAL ⇄ daemon. Exact binary layouts, the `trusted.omnifile` marker, the pending table, and the fail-closed table.
- `docs/contracts/control-api.md` and `service/openapi/control-api.yaml`: edge ⇄ service, plus `enrol` internal signing.
- `docs/design/fsal-namespace.md` (R1): placeholders, the 7-step stub handshake (§5.1), COPY, rewind.
- `docs/design/edge-metadata.md` (R2): the daemon's SQLite replica and feed apply.
- `service/src/omnifile_service/backends/base.py`: the backend contract.

Each track keeps its own lint and tests green: Rust `fmt`, `clippy -D warnings`, `test`; Python `ruff` and `pytest`; C `-Wall -Wextra -Werror` plus the smoke test.

**Shared files:**
- Edge tracks add their crates to `edge/Cargo.toml` `members` by editing only that list.
- Service tracks may add dependencies to `service/pyproject.toml`. Tell the other service track first, and run `uv lock`.

Tracks don't commit. The coordinator reviews and commits each track. New dependencies are listed with their licences for `LICENSES.md`: no AGPL, and no GPL linked into our code.

## Known M0 review carry-overs, fixed in M1

- Ganesha must run under its real systemd unit in CI. CI's `--privileged` hides a dropped `CAP_SYS_ADMIN`, and without it every managed file fails closed.
- Verify `X-Forwarded-Client-Cert`'s format, and that ingress strips any copy a client sends.
- Migrations 0002/0003 were edited in place before release, so dev databases must be rebuilt.

## Open items found during M1

From the FSAL track:
- **Fill race.** The window between the daemon's marker re-check and its fill write is still open. Close it in edge-core's fill, for example with an open-by-handle plus a marker generation compare-and-swap. It must not fill bytes of a version the marker no longer names.
- **COPY into a second OMNI export** judges the destination by the *source* export's policy.
- **The chunk map in the marker** is ignored by the FSAL. The whole non-resident range is treated as missing.
- **NFSv4.1 session slots and the duplicate request cache** while reads are parked: not yet studied.
- **The real systemd run** of Ganesha with this unit belongs to the integration track.

From the edge tracks:
- **The daemon calls `upload_file` directly, bypassing the `omnifile-control` outbox,** so it loses the outbox's restart-survival and idempotent `op_id`s. The integration track wires uploads through the outbox.
- **POSIX metadata format:** uid and gid in decimal, permissions as 4-digit octal (`0644`). The service's Azure backend must use the same format; check it in integration.
- **Fill fence (fsal-socket.md §6.1):** the FSAL must answer DELAY to truncate-to-0 of a PARTIAL file while FETCHING, while disconnected, or between HELLO_ACK and RESYNC_END. Being built by the FSAL track.
- **SMB/local truncation during a fill** stays unguarded until the M2 smb-guard. The fill detects the change and stops, but one in-flight write can land.
- **Linux-only edge tests** (xattr, `O_TMPFILE`, fanotify, xfs) run in the dev VM, not in CI yet. Integration adds an `ubuntu-26.04` lane that runs them as root on an xfs loop volume.
- **Not built yet:** bulk bootstrap and rewind trees.

From M1 integration (exit test 83/83, `tests/e2e/results/latest.md`):
- **Decision:** the appliance Ganesha config sets `MDCACHE { Close_Fast = true; }`. Ganesha otherwise keeps NFSv3 write fds cached indefinitely, and the stub handshake's write-lease check then never lets a v3-written file stub. Costs some NFSv3 write performance.
- **The stub punch also frees xfs's post-EOF preallocation** (`[size, +huge)` with `KEEP_SIZE`), so disk use drops at once rather than after xfs's 300 s eofblocks scan.
- **By design:** on failfast shares, a stub whose data is still online in the cloud is fetched on demand, not refused. Fail fast applies to archived data (ARCHITECTURE §4, step 2).
- **Open:** after an online fetch the catalog still says `stub`; the edge should report `filled`. A failed create is never retried. `omnifile-detect`'s own-writes test is flaky in parallel (CI runs it serially). `e2e.yml` and `edge-linux.yml` haven't run on GitHub yet.
