## Track results and decisions

- **SMB guard:** every measure from the spike design. A-suite (A1–A13, plus O_TRUNC, fence and bad-marker checks) passes on the edge VM, including the 17,000-reader flood: 0 zeros, drained in 10 s. The guard runs inside `omnifile-edge`, which calls `omnifile_smbguard::start()` first in `main`. `edge/systemd/` holds the drop-ins and `install.sh`; a link under `/usr/lib` stops `systemctl disable` dropping the stored group.
  - **Accepted:** an `O_APPEND` write to a stub lands before any fill, because the kernel reports the file position, not EOF. Reads are held (never zeros) while the daemon repairs the file through `stub_extended` (M2 review S3): it fetches the missing range into staging, checks the prefix on disk plus those bytes against the version's CRC, copies them in only if that range is still all holes, marks the file `RESIDENT` (contract §8), and commits it as a new version with the user's appended bytes. If the range holds data or the CRC does not match (not an append), the file is left as it is and reads keep failing with EIO.
  - **Accepted:** the guard journal is a text file on `/run`. It survives daemon restarts, and kernel events don't survive a reboot anyway.
  - **Open:** an `O_TRUNC` landing exactly as a fill writes its last chunk, so the size matches again.
- **Identity and ACL:** permission matrix on the `omnifile-acl` VM: 116 pass, 0 fail, 5 pending until smb-guard is wired, 1 deliberate "before" row. Covers NFS `sys`+`Manage_Gids`, krb5p and SMB, and stub and recalling files over NFS. Explorer edits are enforced over NFS within 10 s. Group removal blocks a new SMB session at once, and NFS after 306 s (winbind cache).
  - **Fix:** a `chmod 0644` locked group members out over NFS, because of Ganesha's POSIX-to-NFSv4 ACL mapping. The edge now normalises "other" and the group mask (`access-control.md` §1.1).
  - **Fix:** Ganesha is built with `ENABLE_VFS_POSIX_ACL=ON`. FSAL_OMNI logs CRIT for an export on a filesystem without ACL support.
  - **Fix:** FSAL READ_INTENT carries the real RPCSEC_GSS level and the Kerberos principal. Verified on krb5p; krb5i is still VERIFY.

## For M2 integration

- Wire `omnifile_smbguard::start(cfg, broker, identity)` first in `main`. Pass `&*handle.marks` as the stub handshake's ignore-mark hook, call `handle.waker.wake(ino)` on fill progress, and install `10-smbguard.conf` only once `start()` is wired.
- Adapt `omnifile_identity::Resolver` into the guard's identity trait.
- The daemon calls `omnifile_acl::to_local` on placeholders, so they inherit the share ACL, and `normalize_inode` on file events.
- The control API's `via` needs a `local` value.
- Carry-overs from M1: after an online fetch the catalog should say `filled`, not `stub`; retry failed creates.
- A CI lane runs the smb-guard A-suite on `ubuntu-26.04` (about 75 min).

## M2 integration results

Exit tests on the dev VMs, integrated tree:
- **M2 exit test: 111/111** (`tests/e2e/m2_exit_test.sh`, `tests/e2e/results/m2-latest.md`):
  - SMB wait and failfast, through smbclient and Kerberos CIFS mounts; each recall is attributed to the AD user's SID;
  - kill -9 of the daemon three times mid-SMB-read, and the daemon held down; no reader saw zeros;
  - a krb5p NFS mount;
  - a 2,000-reader flood;
  - an Explorer ACL edit (smbcacls) reaching the catalog's ACL snapshot.
- **M1 exit test: 83/83.**
- **Permission matrix: 130 pass, 0 pending.**
- **The smb-guard A-suite passes.**

What changed:
- The SMB guard, identity and ACLs (placeholder ACLs, normalisation, drift scans reported through `acls`/`acl-scans`) are wired into the daemon.
- The daemon unit is sandboxed:
  - a capability bounding set; `CAP_SYS_PTRACE` and `CAP_LEASE` are needed and measured, `CAP_KILL` is not;
  - `ProtectSystem=strict`, `NoNewPrivileges`;
  - `SystemCallFilter=~@mount @debug @module @raw-io @reboot @swap @obsolete`, `ProtectKernelTunables`, `RestrictNamespaces`.
- Migration 0007 adds `via: local`.
- New endpoint `files/{id}/filled`, so the catalog says `resident` after an online fetch.
- CI: `e2e.yml` gains an `m2` job, with the AD DC in a container. Its gaps are listed in the workflow header. The A-suite runs in `smbguard.yml`.
