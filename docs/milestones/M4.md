# M4: Teams, portal and policy editor, work breakdown

`docs/BUILD-PLAN.md` M4 says *what*. This file says who builds which part, against which contract. M4 is on branch `claude/m4-portal`, cut from `main` (M0–M3).

## Exit

From the build plan, split by what can prove it.

**Against sim and fakes (the M4 gate, run by the M4 integration track):**
- A stub read by an AD user (a seeded identity with an Entra objectId) sends that user a card through the fake Bot Connector. The card follows the recall through requested → rehydrating → downloading → available.
- The card's buttons are clicked through the **real relay code** (`relay/src/omnifile_relay`, with a test Bot Framework JWKS), which forwards over mutual TLS to `api` `POST /internal/v1/teams/intents`:
  - **Keep online** sets a `keep_online` hold;
  - after an injected restore failure, **Recall** on the "failed" card queues a new recall, and the card follows it to `available`.
- A replayed click, a click by another user, an expired intent and a click by a user who has lost read access are refused, and each refusal is audited.
- When the fake Bot Connector answers 403, the user gets the email fallback through the fake Graph `sendMail`.
- In a browser (Playwright, chromium), against the dev OIDC issuer:
  - an ArchiveAdmin edits a policy and sees the timeline, first-year cost per TB and checks update before saving;
  - the saved version is active and the scheduler re-plans the dataset;
  - a Reader sees only the files their AD groups can read, recalls one ahead of time, and watches the four-step view.
- A policy proposal sent through the partner route (`POST /v1/policies/proposals`, app token) changes nothing until an ArchiveAdmin approves it. The proposer can't approve it.
- Tier pins, rewind (browse as of a date, restore as overwrite or as a restored copy, decision 34), share rewind depth, WORM enable (typed name, lock deadline shown) and the share access screen work end to end on sim.

**Needs a real Teams dev tenant** (listed in `real-tenant-checks.md`, run in pilot 4 or a dev tenant):
- A real Teams user in the dev tenant gets a card for their own stub read.
- Clicking Recall reaches the relay and queues a recall.
- Proactive install works under the client's app policies (risk R5).
- Entra sign-in emits the on-premises SIDs we rely on.

**Needs from pilots:** pilot 4's recall times for 8 GB, 184 GB and 1.2 TB set the ETA table before the portal and cards show times. Until then, ETAs come from `capabilities()` (the provider's stated range, and none above 10 GB), labelled "provider estimate".

## Decisions made for M4

### Portal front end: a TypeScript single-page app

**Decision:** React 19 + TypeScript + Vite, in a new top-level `portal/`. Tests with Vitest, Testing Library and MSW; browser tests with Playwright. The `web` app serves the built files; there is no separate front-end server.

**Why, in a few lines:**
- The JSON API is a product boundary anyway: Prizmanyx uses it. An SPA is its first client, so every screen exercises the contract, and there is one API, not a JSON one plus an HTML one.
- Tracks build in parallel against `portal-api.yaml`: the SPA against MSW mocks generated from it, the back end against contract tests. With server-rendered templates both tracks would edit the same Python handlers.
- The policy editor redraws its timeline, cost and checks as the admin types. The numbers stay server-side (`POST /v1/policies/preview`, debounced 250 ms), so there is still one source of truth. Only the drawing is in the browser.
- htmx with Jinja2 would keep the repo to three languages and avoid a Node lane. That is its real advantage. It loses on the two points above.

**Costs accepted:**
- A fourth language, in the browser only (decision 32).
- One fast, path-filtered CI lane (`portal.yml`).
- A Node build stage in the `web` image. The runtime image stays Python.

**Licences:** React, React Router, TanStack Query, openapi-typescript and openapi-fetch, Vite, Vitest, Testing Library, MSW and ESLint are MIT; TypeScript and Playwright are Apache-2.0. No AGPL, nothing GPL. They go in `LICENSES.md` with the first `package.json`.

### Who answers a Teams click

- The relay holds no bot credentials and no signing key. It forwards the click to `api` and replies to Teams with whatever `api` returns, within Teams' 5 seconds (the relay allows 3).
- **`api` answers synchronously.** It re-verifies the intent, consumes it, does the action in one transaction, and returns `{"result", "card"}`. The card is built by `notify.cards` and carries **no `Action.Execute` buttons**, because `api` holds only the intent *public* keys. It may carry `Action.OpenUrl` to the portal.
- **The worker sends the full card afterwards.** In the same transaction, `api` sends `{"recall_id"}` on `notify` with a 6-second delay. The worker then mints fresh intents and updates the card in place through the Bot Connector. The delay keeps the invoke reply from overwriting the worker's update.
- No Universal Actions `refresh`: the relay refuses non-manual triggers. Every card change after the click is a proactive update.

Detail: `docs/contracts/teams.md` §5.

### Intent signing key

- Ed25519 (`EdDSA`), exactly as the relay verifies (`relay/src/omnifile_relay/intent.py`).
- **Only the worker holds the private key.** `api` and the relay hold the public keys (`{kid: key}` JSON, the relay's `OMNIFILE_RELAY_INTENT_PUBLIC_KEYS` format).
- Azure Key Vault keys can't be Ed25519, so the private key is a Key Vault **secret** (PKCS#8 PEM). The worker reads it with Secrets User on that one secret. Today's Bicep gives the worker no Key Vault role; that is a deploy change (see "For the owner").
- `control-api.md` §13 says "an ES256 key in Key Vault". That is wrong against the built relay. The Teams track corrects §13 and the YAML in M4.

### Keep online from Teams

- The Teams **Keep online** button sets a `keep_online` hold on that one file, for 14 days (decision 33; fixed, not a setting).
- A `keep_online` hold keeps the file resident on the edge (no stub). It changes no cloud tier and costs no provider fee (`policy/engine.py`, `api/stubs.py`).
- Any recipient who can read the file may press it. Tier pins stay with share Owners and DataStewards, in the portal.
- This reads decision 29's "the Teams Keep online button is the same action for one file" as the hold, not as a pin. Owner to confirm.

### Downloads from the portal

- `web` has no storage role, by design (`deploy/azure/main.bicep`).
- So a download is a catalog request: `POST …/downloads` queues a `portal` job. The worker mints a 10-minute read SAS for that one blob version, on the private endpoint, and records it. The browser polls `GET /v1/downloads/{id}` and follows the URL.
- An archived version must be recalled first. The response says so, with the recall options.
- Two needs follow:
  - the worker needs Storage Blob Delegator (a deploy change);
  - the user's browser must resolve and reach the blob private endpoint. That is a real-network check.

### Restore of an old version

- **Decision 34.** A share shows only current versions; older versions are kept as stored blob versions under per-version keys (`<prefix><file_id>/<version_id>`), never as visible files.
- **`overwrite`:** the worker copies the old version to `<prefix>restores/<id>` first, then commits it as a new current content version with `origin = 'service'`. The previous current stays as an older version, so it is never a destructive rollback and WORM is respected.
- **`restored` / `restored_timestamped`:** a new file next to the original, `<stem>-restored<ext>` or `<stem>-restored-<YYYY-MM-DD-HHMMSS>Z<ext>` (UTC). A taken name is `409 name_taken`; the worker re-checks at commit.
- The edge needs no new code. A content-version change from the feed already goes through the narrowing handshake (`omnifile-stub/src/materialize.rs`), so the edge turns its copy into a placeholder of the new version.
- An archived old version is recalled first; the restore waits for it.

### Groups for portal and Teams users

- **Portal:** the ID token carries the user's on-premises SID (`onprem_sid` optional claim). It also carries the `groups` claim, configured to emit **on-premises group SIDs**.
- **Overage** (over 200 groups): `web` queues an `identity_resolve` job and uses the cached `identity.group_sids` until the worker refreshes it from Graph. `web` itself never calls Graph.
- **Teams:** the worker resolves the recipient's groups from Graph (`transitiveMemberOf`) before each card, if the cached list is over an hour old.
- **Both add** the user's domain's Domain Users SID (`<domain SID>-513`, the usual AD primary group, which Entra doesn't sync as a membership) and Authenticated Users (`S-1-5-11`).
- Access is `catalog.acl_can_read(read_sids, deny_sids, user_sid, group_sids)`. Roles never grant read: an ArchiveAdmin sees only what their AD groups can read, plus totals without names (owner to confirm).

### OIDC without secrets

- `web` is a confidential client. It authenticates to Entra's token endpoint with a **client assertion from its managed identity** (a federated identity credential on the app registration), so no client secret is stored. VERIFY on a real tenant.
- Dev and tests use the dev issuer and a static client secret, refused unless `OMNIFILE_DEV_MODE=1`.

## Interfaces between tracks

The Portal API calls the Policy preview track through these, and nothing else. They are pure: no database, no clock (`now` is passed in).

```python
# policy/preview.py
@dataclass(frozen=True)
class ShareFacts:
    share_id: int
    name: str
    protocols: tuple[str, ...]          # nfs3, nfs4, smb
    nfs_sec: tuple[str, ...]            # sys, krb5, krb5i, krb5p
    trust_level: str                    # proven | host_trusted
    on_open: str                        # wait | fail | auto
    wait_threshold_minutes: int | None
    worm_enabled: bool

@dataclass(frozen=True)
class CostAssumptions:
    tb: float = 1.0
    mean_file_bytes: int = 1 << 30      # objects per TB, for per-operation prices
    recall_fraction_per_year: float = 0.0

@dataclass(frozen=True)
class PreviewContext:
    caps: Capabilities
    layout: str                         # two_account | single_account
    shares: Sequence[ShareFacts]
    prices: PriceTable                  # from cost.load_price_table
    assumptions: CostAssumptions = CostAssumptions()

def preview(body: Mapping[str, Any], ctx: PreviewContext) -> PreviewResult: ...
# PreviewResult.to_json() is exactly the PolicyPreview schema in portal-api.yaml.
# An invalid body is not an exception: valid=false, with error checks.
def apply_share_overrides(shares, overrides) -> tuple[ShareFacts, ...]: ...  # request's share_overrides
# CostAssumptions.from_json(request["assumptions"]) raises ValueError when out of range.

# policy/cost.py
def load_price_table(backend_kind: str, override: Mapping[str, Any] | None,
                     *, region: str | None = None) -> PriceTable: ...
# region None: the built-in file's default_region. The override is the API PriceTable
# shape (PriceTable.to_json(), no etag); a bad one raises PriceTableError. sim uses the
# azure_blob table; s3 has none yet (empty table, the preview says price_missing).
def first_year_cost(policy: Policy, ctx: PreviewContext) -> CostEstimate: ...
def pin_cost_change(target: LogicalTier, current: PinFacts, ctx: PreviewContext) -> Money | None: ...
# PinPreview.monthly_cost_change for one file; None when a price is missing.

# policy/checks.py
def policy_checks(body: Mapping[str, Any], ctx: PreviewContext) -> list[Check]: ...
def share_checks(share: ShareFacts, *, restricted_groups: bool) -> list[Check]: ...
def pin_checks(target: LogicalTier, current: PinFacts, ctx: PreviewContext, now: datetime,
               *, until: datetime | None = None, override_archive: bool = False) -> list[Check]: ...
# Check(severity: "error" | "warning" | "info", code: str, message: str, field: str | None,
#       fee: Money | None, share_id: int | None). Codes are listed in portal-api.md §8,
#       plus price_missing (warning). Check.to_json() is the API Check.
```

`PinFacts` (in `policy/checks.py`): `size`, `logical_tier`, `native_class`, `tier_changed_at`, `explicit_tier_set`, `archived`, `smart_layout`, and optional `archive_at` (the file's archive date, for `pin_past_archive_date`).

`CostItem.item` gains `recall`: with `recall_fraction_per_year` above 0, the first-year cost includes one Standard recall of that share of the data archived during the year.

The Teams track's `notify.cards` is the one card renderer. `api/teams.py` and the worker both call `render(state: CardState, audience: Audience, intents: Mapping[str, str] | None) -> dict`. With `intents=None` there are no Execute buttons.
